LUCA Amsterdam — Implementation Notes

Build decisions, tradeoffs, and fixes applied during the rebuild.

1. Booking Page — Critical Fix

Problem: Category/service buttons not clickable

Users could not select categories or individual services in the booking flow. The UI rendered correctly but clicks had no effect.

Root Cause: Babel standalone caching

The booking page used <script type="text/babel"> with Babel Standalone to compile JSX in the browser. Babel caches compiled output aggressively — adding ?v=2 to the URL did not bust Babel's internal compilation cache. Users with stale compiled JSX saw broken event handlers.

Fix: Pre-compile JSX to plain JavaScript

Installed @babel/cli and @babel/preset-react locally, then compiled:

  • reserve.jsx → reserve.js
  • tweaks-panel.jsx → tweaks-panel.js
  • reserve-tweaks.jsx → reserve-tweaks.js

Updated reserve.html to load compiled JS instead of Babel. Switched from React development build to production build for faster loading.

Tradeoff: No more runtime JSX editing

With Babel gone, you cannot edit .jsx files and see changes instantly in the browser. You must run npx babel file.jsx --out-file file.js after each edit. This is the correct tradeoff for production — runtime compilation is a dev convenience, not a production pattern.

2. Asset Optimization

Image format: PNG → WebP

Converted all card images from PNG (~2MB each) to WebP (~65KB each) using cwebp -q 85. 96–97% size reduction. WebP has broad browser support (95%+). No fallback needed for this audience.

Motion format: GIF → WebM VP9

Converted card hover videos and hero from GIF/MP4 to WebM VP9. 3–40x size reduction (6MB GIF → 150KB WebM). Used ffmpeg -c:v libvpx-vp9 -b:v 0 -crf 30 for quality/size balance.

Tradeoff: Safari < 14 lacks WebM

WebM VP9 is not supported in Safari versions before 14 (released Sep 2020). LUCA's audience is Amsterdam wellness seekers — likely on modern iPhones. Added MP4 fallback for hero video only; card videos are decorative and degrade gracefully to static WebP images.

3. i18n Architecture

Translation system: Single-file key-value dictionary

All translations live in i18n.js as a flat dictionary with dot-notation keys (r.cat.sauna, r.svc.sauna60.name). The t(key, lang) function does a simple lookup with fallback to the key itself.

Cache busting strategy

Added ?v=3 to all JS file references in HTML. Babel JSX caches aggressively — this was the only way to force fresh compilation. Now that Babel is gone, ?v=3 still ensures browsers fetch the new compiled JS.

Tradeoff: No translation management UI

Adding/editing translations requires editing i18n.js directly. For LUCA's scale (2 languages, ~200 keys), this is manageable. A CMS or translation platform would be overkill.

4. Homepage Hero Video

Dual-source video element

Hero uses <video> with two <source> children:

  • assets/hero-hero.mp4 (H.264) — primary, broad compatibility
  • assets/hero-woman-sauna-new.webm (VP9) — smaller, modern browsers

Browser picks the first format it supports. MP4 first ensures Safari always works.

5. Subpage Consistency

Navigation pattern

All 8 HTML pages share the same nav structure:

  • Logo → index.html
  • Links: Voorzieningen, Prijzen, Over LUCA, Bezoek (Locatie)
  • Language toggle: NL / EN
  • CTA: "Boek nu" → reserve.html

Only index.html and reserve.html load i18n.js — subpages are Dutch-only for now. Adding i18n to subpages requires loading i18n.js + adding data-i18n attributes to all text elements.

7. OnlineAfspraken.nl Integration (Future)

Current state: Demo mode

The booking flow collects all data (service, date, time, guests, contact info) but does NOT submit to OnlineAfspraken.nl. The "Confirm" button shows a success message but creates no real booking.

Integration path

OnlineAfspraken.nl has a REST API + webhooks. To go live:

  1. Get API credentials from LUCA's OnlineAfspraken portal
  2. Create a serverless function (Netlify Function) to proxy API calls
  3. On confirmation, POST to /appointments with customer + service data
  4. Handle webhook callbacks for booking confirmations/cancellations
